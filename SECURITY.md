 # Security Policy
 
  ## Supported Versions

  This project does not currently maintain multiple release branches.
  Security fixes are applied to the latest version on `main`.

  | Version | Supported          |
  | ------- | ------------------ |
  | latest  | :white_check_mark: |
  | < latest | :x:                |

  ## Reporting a Vulnerability

  Please do **not** open a public issue for security vulnerabilities.

  **Preferred:** Use GitHub's private vulnerability reporting for this
  repository — go to the **Security** tab → **Report a vulnerability**.
  (If you don't see this option, it means private reporting isn't enabled
  yet for this repo — please enable it under
  **Settings → Code security and analysis → Private vulnerability reporting**,
  or let us know via a public issue that you'd like to report privately and
  we'll get it enabled.)

  **Alternative:** Open an issue stating that you have a security report to
  make, without technical details, and a maintainer will follow up with a
  private contact method.

  **What to expect:**
  - Acknowledgment of your report within 7 days.
  - We'll work with you on a coordinated disclosure timeline (90 days from
    acknowledgment is standard, adjustable by mutual agreement).
  - If confirmed, we'll credit you in the fix/advisory unless you prefer
    otherwise.
